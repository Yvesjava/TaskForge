## 1. 技术栈选型与系统架构

### 1.1 技术栈基准

* **后端框架**：Java 17 + Spring Boot 3.x，在 `ruoyi-vue-pro` 项目中新增独立业务模块：`yudao-module-agent`。
* **前端框架**：Vue 3 + TypeScript + Vite + Element Plus，依托 `yudao-ui-admin-vue3` 实现可视化控制台。
* **任务调度与锁**：MySQL 8.0 原生 `FOR UPDATE SKIP LOCKED` 悲观锁无竞争并发调度；Redis 7.x 维护实时状态缓存与租约。
* **沙箱与版本控制**：宿主机维持 Bare Repo 缓存，基于 `git worktree` 实现毫秒级工作区创建与销毁。
* **AI 运行层**：Codex CLI / Claude Code（支持非交互批处理模式），结合 Symphony 规范设计的 `WORKFLOW.md` 系统级提示词。

### 3.2 任务消费调度器与并发锁实现

利用 Spring Task 定时拉取任务，结合 `FOR UPDATE SKIP LOCKED` 防重复消费，并支持多租户忽略：

```java
package cn.iocoder.yudao.module.agent.service.task;

import cn.iocoder.yudao.framework.tenant.core.context.TenantContextHolder;
import cn.iocoder.yudao.framework.tenant.core.util.TenantUtils;
import cn.iocoder.yudao.module.agent.dal.dataobject.task.AgentTaskDO;
import cn.iocoder.yudao.module.agent.dal.mysql.task.AgentTaskMapper;
import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;
import java.time.LocalDateTime;

@Component
@Slf4j
public class AgentTaskScheduler {

    @Resource
    private AgentTaskMapper taskMapper;

    @Resource
    private AgentTaskExecutor taskExecutor;

    @Scheduled(fixedDelay = 3000)
    public void scheduleNextTask() {
        // 使用多租户忽略执行，保证调度器扫描全局待执行任务
        TenantUtils.executeIgnore(() -> {
            // 乐观锁 + 行锁无等待检出
            AgentTaskDO task = taskMapper.selectNextPendingTaskForUpdate();
            if (task == null) {
                return;
            }
            // 抢占任务状态
            int updated = taskMapper.updateStatusIfPending(task.getId(), "RUNNING", LocalDateTime.now());
            if (updated > 0) {
                log.info("[TaskScheduler] 成功抢占任务 id: {}, 任务编号: {}", task.getId(), task.getTaskNo());
                taskExecutor.asyncExecute(task.getId());
            }
        });
    }
}

```

### 3.3 重置状态（Reset）彻底回滚实现
当任务在 `PAUSED` 状态下触发 `resetTask` 时，执行彻底清零：

```java
@Transactional(rollbackFor = Exception.class)
public void resetTask(Long taskId) {
    AgentTaskDO task = taskMapper.selectById(taskId);
    if (!"PAUSED".equals(task.getStatus())) {
        throw exception(TASK_CANNOT_RESET_NOT_PAUSED);
    }

    // 1. 物理移除工作区及所有挂载的 worktree
    worktreeManager.destroyCompositeWorkspace(task.getTaskNo());

    // 2. 清理各项目中已推送到远端或本地的特性分支
    List projects = taskProjectMapper.selectListByTaskId(taskId);
    for (AgentTaskProjectDO proj : projects) {
        gitApiOperator.deleteBranchIfExists(proj.getProjectCode(), task.getTargetBranch());
    }

    // 3. 重置数据库记录回初始状态（保留原文档内容，清空执行痕迹）
    taskMapper.update(null, new LambdaUpdateWrapper()
        .eq(AgentTaskDO::getId, taskId)
        .set(AgentTaskDO::getStatus, "PENDING")
        .set(AgentTaskDO::getExecutionLog, null)
        .set(AgentTaskDO::getDiffStat, null)
        .set(AgentTaskDO::getRetryTimes, 0)
        .set(AgentTaskDO::getCostMs, 0L)
        .set(AgentTaskDO::getStartedTime, null)
        .set(AgentTaskDO::getWorkspacePath, null)
    );
    log.info("[TaskService] 任务 {} 已成功重置，回归待调度状态", task.getTaskNo());
}

```

## 4. Symphony 提示词规范（Prompts 约束设计）

在挂载的工作区根目录下自动渲染并生成 `.ai/WORKFLOW.md`。借鉴 Symphony SPEC 的设计思想，通过严密的系统级提示词规范 Codex 的行为：

```markdown
# Role and Execution Protocol for Coding Agent

You are Symphony-Agent, an automated developer running within an isolated workspace.
Your mission is to read and fulfill the execution requirements specified in `.ai/task.md`.

## Execution Rules (STRICT):
1. **Scope Restriction**: Modify ONLY files within the subprojects listed under `projects` in `.ai/task.md`. Never make any changes outside these directory boundaries.
2. **Phase 1: Implementation**:
   - Read the Execution Plan carefully.
   - For multi-project tasks (e.g. backend and frontend), ensure that API endpoints, DTO models, and parameter names match precisely between frontend client calls and backend controllers.
3. **Phase 2: Verification (Non-Negotiable)**:
   - Once code changes are made, run the exact bash commands defined in `Verification Steps` of `.ai/task.md`.
   - If any test or build fails, read the terminal output, reason through the root cause, and correct your implementation.
   - You are permitted up to 3 self-correction iterations.
4. **Phase 3: Workpad Summary**:
   - Generate a concise summary of changes and validation test results into `.ai/workpad_summary.json` following this format:
     ```json
     {
       "allPassed": true,
       "testsExecuted": ["mvn test -Dtest=OrderTest", "pnpm test"],
       "modifiedFiles": ["backend/src/...", "frontend/src/..."],
       "notes": "Added coupon deduction validation and UI bindings."
     }
     ```
5. **No Terminal Prompts**: Run commands in non-interactive batch mode. Do NOT pause to wait for human confirmation.

```

## 6. 实施路线与演进计划

1. **里程碑 1：数据底座与模块脚手架（1-2 周）**
* 在 `ruoyi-vue-pro` 中引入 `yudao-module-agent` 骨架及相关表结构（V1.0 Flyway/SQL 脚本）。
* 实现 `agent_project` 基础 CRUD，完成 Git 裸库缓存池的本地初始化机制。


2. **里程碑 2：任务控制面与状态流转（2-3 周）**
* 实现 HTTP API 接收本地投递 Markdown 文档并自动解析 FrontMatter。
* 完成基于 MySQL `FOR UPDATE SKIP LOCKED` 的调度器。
* 完整落地 `PAUSED`、`RESUME`、`CANCEL`、`RESET` 与软删除逻辑。


3. **里程碑 3：Worktree 聚合沙箱与 Codex 驱动闭环（3-4 周）**
* 编写 `WorktreeManager`，实现多仓子目录聚合挂载与清理。
* 集成 Symphony 规范的 `.ai/WORKFLOW.md` 提示词，实现 Codex CLI 非交互子进程运行、日志抓取与自验测试指令执行。


4. **里程碑 4：通知集成与自动化合并（4-5 周）**
* 联调企业微信/飞书卡片 Webhook 发送。
* 对接 GitLab/GitHub API 实现分支校验与 Fast-Forward/Squash Merge 自动合入，上线 `yudao-ui-admin-vue3` 完整控制台。
