# TaskForge 工程约定

本文件是 TaskForge 的 harness engineering 基线，固化**代码格式、构建、日志与分支命名**四类约定。`README.md`、`AGENTS.md`、CI（`.github/workflows/ci.yml`）与本地命令必须与本文件保持一致；任意一处调整都要同步其余位置，避免文档与可执行命令漂移。

## 1. 代码格式

### 1.1 通用规则

- 所有文本文件使用 UTF-8；换行统一为 LF；文件末尾保留一个换行；缩进使用空格，不使用 Tab。
- 行尾不留多余空格，Markdown 中用于强制换行的行尾双空格除外。
- 仓库根 `.editorconfig` 供 IDE 实时生效，`.gitattributes` 保证入库换行为 LF；两者是本节的最终裁决。
- 前端目录存在 `frontend/.editorconfig`（`root = true`），前端文件优先使用该文件的规则。

### 1.2 后端（Java / XML / YAML / SQL）

- Java：4 空格缩进；TaskForge 包名统一为 `cn.iocoder.yudao.module.agent`。
- 分层命名沿用 Yudao 约定：`Controller` / `Service` / `ServiceImpl` / `Mapper` / `DO` / `VO` / `ReqVO` / `RespVO` / `Convert`。
- XML（MyBatis Mapper、`pom.xml`）：4 空格缩进；Mapper 的 `namespace`、`id` 必须与 Mapper 接口一一对应。
- YAML / SQL：2 空格缩进；SQL 关键字大写，标识符使用小写下划线，禁止字符串拼接 SQL。
- 后端暂未接入独立格式化插件，提交前通过编译与人工评审保证格式一致（见第 2 节）。

### 1.3 前端（TS / Vue / CSS / SCSS）

- 2 空格缩进，由 ESLint + Prettier + Stylelint 统一；Prettier 关键参数：`printWidth = 100`、`singleQuote = true`、`semi = false`、`trailingComma = 'none'`。
- 修改前端代码后执行：

```powershell
Set-Location frontend
pnpm lint          # eslint + stylelint + prettier 检查（全绿，作为提交门禁）
pnpm lint:eslint   # eslint 自动修复
pnpm lint:style    # stylelint 自动修复
pnpm lint:format   # prettier 自动修复
```

- 现状：`pnpm lint` 在干净仓库上全绿（0 errors），上游遗留告警已由 LZC-67（TASK-BASE-05）修复。提交前请对改动文件执行 `pnpm lint:lint-staged`（或依赖 lint-staged 钩子），不要顺带重排其它模块文件。
- 禁止在源码中硬编码环境地址。本地开发通过 `frontend/.env.local`（模板 `frontend/.env.local.example`）注入；非本地构建 `dev/test/stage/prod` 分别通过受控提交的 `frontend/.env.dev` / `.env.test` / `.env.stage` / `.env.prod` 注入，其域名均为占位值，部署前替换为真实网关地址，严禁写入真实凭证。

## 2. 构建与验证

提交前至少执行与改动范围对应的命令，CI 使用同一组门禁命令（`.github/workflows/ci.yml`）。

### 2.1 根目录

```powershell
docker compose config      # 校验 Compose 配置
git diff --check           # 校验空白与冲突标记
```

### 2.2 后端（Java 17 + Maven 3.8+）

```powershell
Set-Location backend
mvn -B clean test-compile                                        # 全量编译（与 CI 一致）
mvn -q -pl yudao-module-agent/yudao-module-agent-biz -am test-compile   # agent 模块定向编译
mvn -pl yudao-module-agent/yudao-module-agent-biz -am test       # agent 模块单元测试
mvn -pl yudao-server -am -DskipTests package                     # 打包可运行 server
```

### 2.3 前端（Node.js 20.19+ / pnpm 8.6+）

```powershell
Set-Location frontend
pnpm install --frozen-lockfile   # 与 CI 一致，不更新锁文件
pnpm dev                         # 本地开发，监听 3000，API 指向 48080
pnpm lint                        # eslint + stylelint + prettier（全绿，作为提交门禁）
pnpm ts:check                    # TypeScript 类型检查
pnpm build:local                 # 本地构建（--mode env.local，加载 .env.local）
pnpm build:dev                   # dev 环境构建（--mode dev，加载 .env.dev）
pnpm build:test                  # test 环境构建（--mode test，加载 .env.test）
pnpm build:stage                 # stage 环境构建（--mode stage，加载 .env.stage）
pnpm build:prod                  # 生产构建（--mode prod，加载 .env.prod；与 CI 一致）
```

### 2.4 门禁清单

- 后端：`mvn -B clean test-compile` 通过。
- 前端：`pnpm install --frozen-lockfile && pnpm lint && pnpm run build:prod` 通过（CI 门禁，`pnpm lint` 必须 0 errors）。
- 文档与配置：`git diff --check` 无告警。
- 涉及启动链路时补充：`docker compose up -d`、`docker compose ps`、`http://localhost:48080/v3/api-docs`、`http://localhost:3000/`。

## 3. 日志

后端日志配置位于 `backend/yudao-server/src/main/resources/logback-spring.xml`：本地根级别为 `INFO`，输出到控制台与文件，文件按天 + 10MB 滚动并保留 30 天。

- 级别选择：`ERROR` 用于需要人工介入的失败；`WARN` 用于可自愈或已降级的异常；`INFO` 记录状态流转、调度、合并、通知等关键事件；`DEBUG` 仅在排障时临时开启，不进入默认配置。
- 结构化字段：关键事件日志携带任务编号、执行代次、仓库标识、状态前后值等字段；跨模块调用与错误响应携带 `TracerUtils.getTraceId()`（OpenTelemetry TraceId，可能为空字符串）。
- 可追溯：状态流转、租约抢占、合并结果必须留下日志或操作记录（`agent_task_operation_log`），不得只用异常堆栈代替业务日志。
- 脱敏：Git 凭证、Token、Cookie、`Authorization` 头、私钥、数据库口令和完整环境变量一律不得写入日志或错误响应；`git_url`、子进程命令参数进入日志前先脱敏。
- Worker 子进程：Codex 与自验命令的 stdout/stderr 全量落盘到任务日志；写入 `execution_log` 前按上限截断（保留头部与尾部），并记录截断标记与原始日志路径。
- 禁止提交日志文件：`.gitignore` 已忽略 `backend/**/logs/` 与 `*.log`。

## 4. 分支与提交

### 4.1 分支命名

- 格式：`<type>/<ticket-id>-<short-slug>`，全小写、短横线分词，例如 `feat/lzc-9-engineering-conventions`。
- `<type>` 与 Conventional Commits 类型一致：`feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `perf` / `build` / `ci`。
- 主干为 `main`；特性分支从最新 `origin/main` 创建，合并前先把 `origin/main` 合入本分支并重跑第 2 节校验。
- 禁止对共享分支 force push，禁止重写已推送历史。

### 4.2 提交信息

使用 Conventional Commits：`<type>(<scope>): <subject>`。TaskForge 业务提交 `scope` 统一为 `agent`，例如 `feat(agent): 新增项目 CRUD`；纯文档提交可省略 `scope`，例如 `docs: 固化工程约定`。

### 4.3 PR

- PR 目标分支为 `main`，并打 `symphony` 标签。
- PR 描述包含变更范围、验证命令与结果、风险与回滚方式。
- 通过第 2 节门禁后方可进入评审；评审意见需逐条解决，或在对应线程给出明确理由。

## 5. 模块与目录边界

见 `AGENTS.md` 的 Module Boundary：后端业务代码只放在 `backend/yudao-module-agent/`；前端 API 与类型放在 `frontend/src/api/`，页面放在 `frontend/src/views/`，组件放在 `frontend/src/components/`。不要修改无关的基础设施模块（`yudao-framework`、`yudao-server`、`yudao-module-system`、`yudao-module-infra` 等）。
