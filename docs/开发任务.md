# TaskForge 开发任务清单

本文档依据 [开发模块与子任务拆分](开发模块与子任务拆分.md) 的第 3 节模块总览与第 5 节一级子任务目录，将每个模块收敛为**一个模块级开发任务**。任务编号使用模块编号（如 `TASK-BASE`），其下的一级子任务编号沿用拆分文档（如 `TASK-BASE-01`），用于排期与验收。

每个任务遵循拆分文档第 7 节的模板字段。依赖关系与里程碑映射见拆分文档第 4、6 节。

> 状态约定：`TODO` / `IN_PROGRESS` / `BLOCKED` / `DONE`。首批优先建立最小闭环 `BASE -> DATA -> PROJECT -> DOC -> TASK -> SCHED -> WORK -> EXEC`。

## TASK-BASE 工程基线与环境

- **模块**：`BASE`
- **目标**：建立可重复启动、可编译的开发环境与构建规范，为后续模块提供脚手架与统一约定。
- **前置任务**：无
- **影响范围**：后端 Maven 模块、前端 Vite 工程、Docker Compose、本地配置
- **输入契约**：README、`local/taskforge` 配置、`docker-compose.yml`、`AGENTS.md`
- **实现内容**：
  - `TASK-BASE-01` 注册 `yudao-module-agent` 的 Maven 模块与包结构
  - `TASK-BASE-02` 固化 `local,taskforge` 配置、Docker Compose、MySQL/Redis 启动参数
  - `TASK-BASE-03` 统一前端 API 环境变量、端口与本地开发命令
  - `TASK-BASE-04` 建立格式、构建、日志与分支约定
- **交付物**：可编译后端骨架、可启动 Docker 环境、`pnpm dev` 可用、README 与 AGENTS.md
- **验收命令**：`mvn -pl yudao-module-agent -am clean package -DskipTests`；`docker compose up -d mysql redis`；`pnpm install && pnpm dev`
- **验收条件**：新环境按 README 启动并通过健康检查；前后端构建通过；实际命令与文档一致
- **风险与回滚**：环境脚本回退到上一可用版本；Docker 卷与数据库可重建
- **状态**：`DONE`

## TASK-DATA 数据底座

- **模块**：`DATA`
- **目标**：落地四类表的迁移、DO/Mapper 与审计字段，为所有持久化模块提供数据契约。
- **前置任务**：`TASK-BASE`
- **影响范围**：数据库迁移、后端 DAL（DO/Mapper/XML）
- **输入契约**：技术架构文档第 2 节表结构（`agent_project`、`agent_task`、`agent_task_project`、`agent_task_operation_log`）
- **实现内容**：
  - `TASK-DATA-01` 创建四类表迁移脚本（Flyway/SQL，含回滚说明）
  - `TASK-DATA-02` 实现 DO、Mapper、XML 与查询条件
  - `TASK-DATA-03` 补齐租户、软删除、乐观锁、执行代次与审计字段约束
  - `TASK-DATA-04` 编写数据库约束与并发查询集成测试
- **交付物**：可重复执行的迁移脚本、持久化模型、数据访问集成测试
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*MapperTest,*MigrationTest'`
- **验收条件**：迁移可重复执行且可回滚；唯一键、索引、`FOR UPDATE SKIP LOCKED` 行为可验证；字段与架构文档一致
- **风险与回滚**：提供回滚脚本；索引调整前备份既有数据
- **状态**：`DONE`

- **输入契约**：产品文档 3.5 节（Front Matter 字段、Markdown 小节、示例）
- **实现内容**：
  - `TASK-DOC-01` YAML Front Matter 解析与字段类型转换
  - `TASK-DOC-02` 必填字段、状态值、项目、分支与子目录校验
  - `TASK-DOC-03` 正文小节与可执行验收步骤校验
  - `TASK-DOC-04` 投递 API、任务编号生成与文档版本保存
  - `TASK-DOC-05` 暂停任务的文档编辑与乐观锁
- **交付物**：文档解析器、校验器、投递 API、幂等与乐观锁测试
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*DocumentParserTest,*SubmitTaskTest'`
- **验收条件**：单仓/多仓示例均可解析且错误含字段位置；缺字段、重复目录、未启用项目被拒绝；重复幂等键不重复建任务；版本冲突不覆盖他人修改

## TASK-TASK 任务控制面与状态机

- **模块**：`TASK`
- **目标**：固化状态枚举与转换矩阵，提供统一的控制面 API 与操作审计。
- **前置任务**：`TASK-DATA`、`TASK-DOC`
- **影响范围**：后端模块、控制面 API、审计日志
- **输入契约**：产品文档 3.2 节、技术架构文档 3.7~3.9 节状态矩阵
- **实现内容**：
  - `TASK-TASK-01` 固化状态枚举、合法转换矩阵与条件更新
  - `TASK-TASK-02` 暂停、恢复、取消、重新入队与软删除
  - `TASK-TASK-03` Resetting 流程、清理委托与恢复结果
  - `TASK-TASK-04` 验收、打回与合并冲突人工处理入口
  - `TASK-TASK-05` 操作审计、请求幂等键与统一错误响应
- **交付物**：状态机服务、控制面 API、审计记录与幂等测试
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*StateMachineTest,*IdempotencyTest'`
- **验收条件**：所有状态动作有统一服务入口；非法状态操作返回 `409` 且不改数据；重试请求不产生重复副作用；审计记录不可变
- **风险与回滚**：状态变更只经状态机服务，回退通过条件更新保证一致性
- **状态**：`DONE`

## TASK-SCHED 调度与 Worker 租约

- **模块**：`SCHED`
- **目标**：实现短事务抢占、Redis 租约、取消信号与超时恢复。
- **前置任务**：`TASK-TASK`
- **影响范围**：后端调度器、Redis 租约、恢复任务
- **输入契约**：技术架构文档 3.2 节（调度器、抢占 SQL、Redis 键）
- **实现内容**：
  - `TASK-SCHED-01` 按优先级与创建时间的短事务抢占
  - `TASK-SCHED-02` Redis 租约、心跳与执行代次校验
  - `TASK-SCHED-03` 取消信号与 Worker 停止写入规则
  - `TASK-SCHED-04` 租约过期扫描与失败恢复
  - `TASK-SCHED-05` 调度器指标与运行状态检查
- **交付物**：调度器、租约服务、恢复任务、指标
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*ClaimServiceTest,*LeaseRecoveryTest'`
- **验收条件**：仅一台 Worker 获得同一任务；续租只允许当前 Worker 与代次；失租后不再提交/推送/写回；过期任务进入 `FAILED` 或恢复队列且旧 Worker 无法覆盖结果
- **风险与回滚**：事务不包围外部操作；恢复动作带代次校验
- **状态**：`DONE`

- **模块**：`WORK`
- **目标**：实现 Bare Repo 缓存、多仓 Worktree、分支与幂等清理。
- **前置任务**：`TASK-PROJECT`、`TASK-SCHED`
- **影响范围**：后端工作区编排、Git 适配器
- **输入契约**：技术架构文档 3.4 节（目录布局、创建/清理流程）
- **实现内容**：
  - `TASK-WORK-01` Bare Repo 缓存初始化、拉取与锁定
  - `TASK-WORK-02` 多仓 Worktree 创建与聚合目录布局
  - `TASK-WORK-03` 任务分支创建、基线校验与分支清理
  - `TASK-WORK-04` 工作区路径校验、并发互斥与残留检测
  - `TASK-WORK-05` 幂等清理与 Git 命令错误归一化
- **交付物**：工作区编排器、Git 适配器、清理器
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*WorktreeManagerTest'`
- **验收条件**：项目首次使用可初始化且重复使用不破坏缓存；子目录按映射挂载；无法逃逸工作根目录；重复清理成功且错误含仓库与操作上下文
- **风险与回滚**：创建失败按已挂载项目倒序清理；清理幂等可重试

## TASK-EXEC AI 执行与自验

- **目标**：以非交互子进程驱动 Codex/Claude，执行计划与验收命令并写回结果。
- **前置任务**：`TASK-WORK`、`TASK-SCHED`
- **影响范围**：Worker 执行链、`.ai/WORKFLOW.md`、日志与报告
- **输入契约**：技术架构文档 3.5 节与第 4 节 Symphony 提示词
- **实现内容**：
  - `TASK-EXEC-01` 固化 `.ai/WORKFLOW.md` 与任务文档注入协议
  - `TASK-EXEC-02` 非交互子进程启动与进程组管理
  - `TASK-EXEC-03` 构建、测试命令白名单与顺序执行
  - `TASK-EXEC-04` 最多两次自修复重试与结果归档
  - `TASK-EXEC-05` 超时、资源限制、失败清理与结果写回
- **交付物**：Worker 执行链、日志采集、测试报告、假 Codex 测试
- **验收命令**：`mvn -pl yudao-module-agent/yudao-module-agent-biz -am test -Dtest='*CodexRunnerTest'`
- **验收条件**：Codex 能读取任务目标、计划与约束；所有验收命令通过后才允许提交推送；每次重试有独立日志/耗时/原因；超时终止完整进程组并进入 `FAILED`
- **风险与回滚**：禁止 `force push`；失败清理幂等可重试
- **状态**：`DONE`
