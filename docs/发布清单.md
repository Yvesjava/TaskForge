## 4. 灰度观察项

### 4.1 无重复提交

```sql
-- 同一租户内同一操作幂等键只允许一条审计记录
SELECT request_idempotency_key, tenant_id, COUNT(*)
FROM agent_task_operation_log
GROUP BY request_idempotency_key, tenant_id
HAVING COUNT(*) > 1;

-- 任务编号唯一（含软删除状态）
SELECT task_no, tenant_id, deleted, COUNT(*)
FROM agent_task
GROUP BY task_no, tenant_id, deleted
HAVING COUNT(*) > 1;
```

- [ ] 两条查询均返回 0 行

### 4.2 无租约泄漏

```sql
-- 运行中任务不得存在空租约或过期租约
SELECT COUNT(*)
FROM agent_task
WHERE status = 'RUNNING' AND deleted = 0
  AND (lease_until IS NULL OR lease_until < NOW());

-- 运行中任务必须持有 Worker
SELECT COUNT(*)
FROM agent_task
WHERE status = 'RUNNING' AND deleted = 0
  AND (worker_id IS NULL OR worker_id = '');
```

```bash
# Redis 永久残留租约键（TTL = -1）应为 0；有 TTL 的键会按租约 + 缓冲自动过期
docker compose exec -T redis redis-cli -a taskforge_dev --scan --pattern 'agent:task:*'
```

- [ ] 运行中任务无过期/空租约
- [ ] 运行中任务均持有 Worker
- [ ] 无 Redis 永久租约键

### 4.3 无残留进程与工作区

```powershell
# 工作区根目录下不应残留 dirA-{taskNo}
Get-ChildItem C:\data\agent-workspace -Directory -Filter 'dirA-*'

# 不应残留 Codex/Claude 或指向工作区/裸仓库缓存的进程
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -in @('codex.exe','claude.exe') -or
                 ($_.CommandLine -and ($_.CommandLine.Contains('agent-workspace') -or $_.CommandLine.Contains('agent-bare-repos'))) }
```

- [ ] 无 `dirA-*` 残留目录
- [ ] 无残留 Codex/Claude 进程

## 5. 回滚演练

数据库迁移回滚脚本为 `backend/yudao-module-agent/yudao-module-agent-biz/src/main/resources/db/rollback/rollback-all-agent-tables.sql`。

1. 备份 TaskForge 业务表：

```powershell
docker compose exec -T mysql mysqldump -uroot -ptaskforge_dev taskforge `
  agent_project agent_task agent_task_project agent_task_operation_log agent_ops_alert agent_notice_outbox > agent-tables-backup.sql
```

2. 执行回滚脚本：

```powershell
Get-Content backend/yudao-module-agent/yudao-module-agent-biz/src/main/resources/db/rollback/rollback-all-agent-tables.sql |
  docker compose exec -T mysql mysql -uroot -ptaskforge_dev taskforge
```

3. 验证业务表已删除、Flyway 版本记录已清理：

```sql
SHOW TABLES LIKE 'agent%';
SELECT version, description FROM flyway_schema_history WHERE version IN ('1','2','3','4','5','6','7','8','9');
SELECT COUNT(*) FROM system_menu WHERE deleted = 0 AND (permission LIKE 'agent:%' OR (parent_id = 0 AND type = 1 AND path = '/agent'));
```

4. 重启后端，Flyway 自动从 V1 开始重新执行全部迁移并恢复表结构与菜单种子：

```powershell
java -jar backend/yudao-server/target/yudao-server.jar --spring.profiles.active=local,taskforge
```

5. 再次验证表存在且版本记录完整。

- [ ] 回滚后 `agent_*` 业务表被删除
- [ ] 重启后 Flyway 重新迁移成功
- [ ] 回滚过程有备份，且步骤可重复执行

## 6. 升级/回退策略

- 灰度问题优先回滚到上一可用镜像或上一个 Git 提交，恢复数据库备份。
- 应用层回退：停后端 -> 执行数据库回滚脚本 -> 部署上一版本 jar -> 重启并验证。
- 数据库备份在回滚前必须生成，回滚后校验表结构与关键数据。
- 灰度范围逐步扩大：本次单 Worker、单租户、非生产仓库通过后再扩大并发、租户与仓库范围。
